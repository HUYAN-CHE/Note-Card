## 1. 概述

### 1.1 背景与动机

《记事卡》是一个"把一件事说清楚、找对人来帮忙"的互助协作工具。用户把待办/需求写成一张"记事卡"，通过一度人脉（好友）或直接邀请，把卡推给能帮上忙的人；好友看到卡后既能被动浏览二度人脉，也能主动"介绍给朋友"——把卡连同自己的关系链转给更匹配的人，形成可溯源的"互助网络"。

核心洞察：在微信生态中，大量协作需求散落在聊天里——帮朋友找资源、约人、询问信息、协调事务。用户不想拉群、不想在聊天里反复翻。《记事卡》介于"待办清单"与"熟人协作网络"之间：比待办多了**人脉协作**，比社群轻了**建群负担**。

### 1.2 目标

- **业务目标**：打造微信小程序内闭环的轻量协作工具，通过关系链扩散形成网络效应
- **用户目标**：让"一件事"和"能解决它的人"高效连接，降低协作门槛
- **成功指标**：
  - 北极星指标："聊到→结构化草稿就绪"从分钟级降到秒级
  - 护栏指标：邀请接受率、单卡协作完成率、二度扩散率
  - 成本指标：单卡 AI 调用成本压到免费额度内

### 1.3 范围

- **本期包含（MVP，v1.1 现状）**：
  - 8 个主页面：事项（首页）、互助、我的主页、记事卡详情、新建/编辑记事卡、从聊天整理、消息中心、会员
  - 核心功能：记事卡 CRUD、邀请协作（微信分享直达）、二度人脉浏览与引荐制申请、从聊天一键整理（A+C方案）、状态三态（系统判定）、提醒订阅（全局共享额度+按卡标记）、消息中心站内通知
  - AI 能力（P0）：混元语义结构化、智能协助者推荐
- **本期不包含**：
  - 群协作（多创作者）
  - 自动支付/积分体系（会员为管理员人工开通）
  - 跨平台（仅微信小程序）
  - 实时聊天（依赖微信原生）

## 2. 用户画像

### 2.1 角色定义

| 角色 | 身份 | 核心目标 | 主要痛点 |
|------|------|----------|----------|
| **创作者**（如：胡晓） | 发起记事卡的人 | 把聊天里的事变成卡，邀请能帮的人，跟进进度到办成 | 信息散落在聊天里，无沉淀；不确定该找谁帮忙 |
| **一度协助者**（如：王姐） | 被直接邀请的好友 | 收到邀请后接受，参与推进待确认，完成协作 | 协作进度不透明，不知道要做什么 |
| **二度访客**（如：小林） | 好友的好友 | 浏览扩散来的卡，找到能帮上忙的事申请加入 | 不知道朋友的朋友需要什么，缺少连接渠道 |

### 2.2 用户旅程地图（创作者主线）

| 阶段 | 情绪 | 动作 | 触点 | 痛点 | 机会 |
|------|------|------|------|------|------|
| 1·触发 | 😟 | 微信聊到一件事，怕忘 | 微信会话 | 信息散落，无沉淀 | 一键从聊天整理 |
| 2·创建 | 😀 | A转发/C复制→预览→生成 | 微信AI+小程序 | 不想从头填表单 | 自动识别+可勾改 |
| 3·发布邀请 | 🙂 | 填协助者/可见性→发布 | 小程序+分享卡片 | 不确定该找谁 | 聊天识别协助者候选 |
| 4·协作中 | 😌 | 协助者接受、推进进度 | 小程序内协作 | 进度不透明 | 状态三态徽标+截止提醒 |
| 5·二度扩散 | 🤔 | 申请加入需引荐+审批 | 互助页+消息中心 | 流程打断心流 | 转发引荐+站内消息通知 |
| 6·收尾 | 😄 | 事办成，卡片到期转已过期 | 小程序闭环 | 办完无正反馈 | 过期消息通知+信任沉淀 |

## 3. 用户故事

### 3.1 创作者（Creator）

**US-C01**：作为创作者，我想要从微信聊天一键生成记事卡，以便不用在小程序内从头填写。
**US-C02**：作为创作者，我想要邀请微信好友当协助者，以便把卡推给能帮上忙的人。
**US-C03**：作为创作者，我想要设置卡的可见性（仅协助者/二度可看），以便控制隐私范围。
**US-C04**：作为创作者，我想要审批二度访客的加入申请，以便确保协作质量。
**US-C05**：作为创作者，我想要看到协助者的进度更新，以便掌握协作状态。
**US-C06**：作为创作者，我想要订阅卡的截止提醒，以便不错过跟进时机。
**US-C07**：作为创作者，我想要在消息中心集中查看申请、引荐、审批结果和过期通知，以便不漏掉协作动态。

### 3.2 一度协助者（1° Helper）

**US-H01**：作为一度协助者，我想要收到提醒通知，以便及时知道协作动态和截止时间。
**US-H02**：作为一度协助者，我想要查看记事卡详情和待确认事项，以便了解要做什么。
**US-H03**：作为一度协助者，我想要更新进度和补充信息，以便推进协作。
**US-H04**：作为一度协助者，我想要帮二度好友"引荐"给卡主，以便把卡转给更合适的人。

### 3.3 二度访客（2° Visitor）

**US-V01**：作为二度访客，我想要在互助页浏览好友的朋友的需求，以便找到能帮上忙的事。
**US-V02**：作为二度访客，我想要申请加入感兴趣的记事卡，并请共同好友帮我引荐，以便参与协作。
**US-V03**：作为二度访客，我想要看到申请状态（待引荐/待审批/已拒绝），以便知道下一步该做什么。

## 4. 功能需求

### 4.1 功能清单

#### 核心功能（Must Have）

| 编号 | 功能名称 | 用户故事 | 功能描述 | 输入/输出/交互 |
|------|----------|----------|----------|----------------|
| F-001 | 事项首页 | US-C01 | 我创建的/与我相关的记事卡列表（状态三态徽标）；"从聊天整理"快捷入口；FAB新建 | 列表数据、点击跳转 |
| F-002 | 从聊天整理 | US-C01 | A路径：转发微信AI结构化；C路径：剪贴板识别；②路径：选文件 | 聊天文本/图片→结构化草稿→预览页 |
| F-003 | 整理预览 | US-C01 | 标题/描述/待确认/协助者候选四块，默认全勾选，可取消编辑 | 结构化数据→用户确认→生成卡片 |
| F-004 | 新建/编辑记事卡 | US-C01,US-C03 | 标题→描述→待确认→协助者→可见性开关的线性分组 | 表单输入→保存草稿/发布 |
| F-005 | 记事卡详情 | US-C05 | 详情+协助者+待确认+进度；三种身份视图；状态徽标点击弹「状态说明」；邀请/申请双入口分流 | 卡ID→按身份与入口渲染不同视图 |
| F-006 | 邀请协作 | US-C02 | 详情页「邀请协作」→ 微信分享（path 带 ref 短码或裸 id）→ 被邀请人打开显示「接受邀请」→ 直接加入并建一度关系；接受成功后无头像者弹授权补全 | 分享卡片→接受邀请→建立Relationship（degree=1） |
| F-007 | 互助页 | US-V01 | 一度人脉横滑→点击刷新下方二度人脉卡片（状态仅区分已过期/进行中）；hero 区右上角消息胶囊+订阅胶囊；空态引导 | 一度列表→二度卡列表→点击进入详情（view=network） |
| F-008 | 申请加入（引荐制） | US-V02 | 二度访客经互助页进入提交申请；有引荐人时 status=pending_intermediary 待引荐，无引荐人直接 pending 待审批；创作者审批 | 申请表单→引荐→审批流程→建立二度关系 |
| F-009 | 转发引荐 | US-H04 | 申请人将待引荐申请转发给一度好友（path 带 endorse=requestId），好友打开点「帮 TA 引荐」，校验通过后转 pending | 分享申请卡→好友引荐→通知创作者 |
| F-010 | 我的主页 | US-C06 | 个人资料+未设提醒/提醒中/已过期/协助的事四分类标签+互助统计 | 用户ID→统计数字+列表 |
| F-011 | 提醒订阅 | US-C06,US-H01 | 授权一次=推一条，users.subscribeCount 全局共享额度；订阅同时按卡记录 reminderSetBy；sendReminder 每日 9:00 扫「明天截止」的卡推送（模板 15788 待办事项提醒），发一条额度-1 | 订阅动作→额度+1/按卡标记→每日定时推送 |
| F-017 | 消息中心 | US-C07 | 站内收件箱：卡片过期/提醒/申请引荐/审批结果/会员五类消息；类型色点+相对时间+未读绿点；互助页消息胶囊显示未读数 | 事件写入→列表→按类型跳转/进入全量已读 |

### 4.2 非功能需求

| 维度 | 要求 |
|------|------|
| **性能** | 首屏加载 < 2s；列表滚动 60fps；AI结构化响应 < 3s |
| **安全** | 混元API Key仅存云开发环境变量，端上不暴露；调用走云函数 |
| **可用性** | 微信小程序原生体验；正文14px起；触控目标≥44px |
| **可扩展性** | 关系链当前实现一度/二度两级，度数可扩展；数据模型预留字段 |
| **易用性** | 浅/深双主题；状态文字+色彩双编码；教育性空状态 |
| **兼容性** | 微信小程序基础库 2.30+；iOS/Android 兼容 |

## 5. 优先级

### 5.1 MoSCoW 矩阵

| 编号 | 功能名称 | 优先级 | 理由 |
|------|----------|--------|------|
| F-001 | 事项首页 | **Must** | 核心入口，没有无法使用 |
| F-002 | 从聊天整理 | **Must** | 核心差异化功能，降低创建门槛 |
| F-003 | 整理预览 | **Must** | F-002的必要后续 |
| F-004 | 新建/编辑记事卡 | **Must** | 核心创建流程 |
| F-005 | 记事卡详情 | **Must** | 核心查看/协作页面 |
| F-006 | 邀请协作 | **Must** | 协作关系建立的关键 |
| F-007 | 互助页 | **Must** | 二度扩散的核心入口 |
| F-008 | 申请加入 | **Must** | 二度协作闭环 |
| F-009 | 转发引荐 | **Must** | 二度引荐的核心机制 |
| F-010 | 我的主页 | **Must** | 个人中心+统计 |
| F-011 | 提醒订阅 | **Must** | 截止提醒闭环 |
| F-017 | 消息中心 | **Must** | 站内通知闭环的承载 |
| F-012 | AI语义结构化 | **Should** | 体验升级，本地规则可兜底 |
| F-013 | 智能协助者推荐 | **Should** | 邀请体验优化 |
| F-014 | 进度摘要 | **Could** | 体验增厚，非必需 |
| F-015 | 语音建卡 | **Won't** | 本期不做，留待后续 |
| F-016 | 信任分模型 | **Won't** | 数据积累后再做 |

**占比统计**：Must 12/17（71%）| Should 2/17（12%）| Could 1/17（6%）| Won't 2/17（12%）

> Must 占比略超60%，因MVP阶段核心功能必须全部上线。AI功能由Should/Could承担，确保核心流程不受影响。

### 5.2 版本规划建议

- **MVP（v1.0）**：F-001~F-011（所有 Must Have）
- **v1.1（2026-08-08，已上线）**：消息中心（F-017）、状态三态体系、邀请/申请双链路与引荐制、提醒订阅额度制、头像授权补全
- **v1.2**：F-012 + F-013（AI 能力上线）
- **v2.0**：F-014 + 评估信任分模型

## 6. 验收标准

### 6.1 F-001 事项首页

**AC-F001-01**：正常加载
```
Given 用户已登录且创建了至少1张记事卡
When 打开事项首页
Then 按更新时间倒序展示记事卡列表，每张卡显示标题+状态三态徽标（未设提醒/提醒中/已过期）+协助者头像+更新时间
```

**AC-F001-02**：空状态引导
```
Given 用户未创建任何记事卡
When 打开事项首页
Then 展示教育性空状态：插画+"还没有记事卡"+"下拉或点击上方按钮，从聊天记录生成一张记事卡"
```

**AC-F001-03**：快捷入口
```
Given 用户在事项首页
When 点击"从聊天整理"快捷入口
Then 跳转到从聊天整理页（/pages/card-import/card-import）
```

### 6.2 F-002 从聊天整理

**AC-F002-01**：剪贴板识别（C路径）
```
Given 用户已复制微信聊天内容
When 打开从聊天整理页
Then 自动检测剪贴板内容，显示"检测到剪贴板内容"卡片，点击"粘贴并整理"进入预览
```

**AC-F002-02**：空剪贴板处理
```
Given 用户剪贴板为空
When 打开从聊天整理页
Then 显示引导提示"去微信复制聊天内容，或选择图片/文件"，提供选文件入口
```

**AC-F002-03**：隐私声明
```
Given 用户在从聊天整理页
Then 页面顶部显示隐私声明："记事卡不会主动读取微信消息，以下内容都需你主动复制或选择"
```

### 6.3 F-003 整理预览

**AC-F003-01**：字段展示与勾选
```
Given 用户已完成剪贴板粘贴或AI结构化
When 进入整理预览页
Then 展示标题/描述/待确认/协助者候选四个区块，默认全部勾选，可取消勾选或编辑内容
```

**AC-F003-02**：生成记事卡
```
Given 用户在整理预览页已勾选至少一个字段
When 点击"生成记事卡"
Then 跳转到新建记事卡页，已勾选字段自动预填，未勾选字段留空
```

### 6.4 F-004 新建/编辑记事卡

**AC-F004-01**：表单填写
```
Given 用户在新建记事卡页
When 填写标题（必填）、描述、待确认事项、协助者、可见性开关
Then 可以保存为草稿或点击"邀请一起用"发布
```

**AC-F004-02**：可见性开关
```
Given 用户在新建记事卡页
When 开启"让朋友的朋友也能看到"
Then 该卡发布后可在互助页被二度人脉浏览；关闭则仅协助者可见
```

**AC-F004-03**：标题校验
```
Given 用户未填写标题
When 点击发布
Then 阻止提交，提示"请输入标题"
```

### 6.5 F-005 记事卡详情

**AC-F005-01**：创作者视图
```
Given 用户是卡的创作者
When 进入记事卡详情
Then 显示完整管理权限：可编辑内容、可邀请协作、可审批加入申请
```

**AC-F005-02**：一度协助者视图
```
Given 用户是卡的一度协助者
When 进入记事卡详情
Then 显示协作视图：可查看全部内容、可更新待确认、不可编辑标题/描述
```

**AC-F005-03**：二度访客视图（申请入口）
```
Given 用户是二度访客，经互助页进入（URL 带 view=network）
When 进入记事卡详情
Then 显示只读视图，底部为申请按钮组：无申请时"申请加入"；待引荐时"待引荐 · 转发给好友引荐"；待审批时"已申请，等待通过"（灰态）；已拒绝时"申请已被拒绝 · 重新申请"
```

**AC-F005-04**：被邀请人视图（邀请入口）
```
Given 用户经分享链接/扫码进入（ref 短码、裸 id 或 scene，均非 view=network）
When 进入记事卡详情且非创作者/协助者
Then 底部显示"接受邀请"，点击直接加入，无需申请
```

**AC-F005-05**：状态说明弹窗
```
Given 用户在记事卡详情页
When 点击状态徽标
```

### 6.8 F-008 申请加入（引荐制）

**AC-F008-01**：申请提交（带引荐人）

**AC-F008-02**：直接申请（无引荐人）

```
Then 通过：申请人加入协助者、双方建立二度关系（degree=2，source=join_request）；无论通过/拒绝均写 join_result 消息通知申请人
```

**AC-F008-04**：重新申请
```

```

## 7. 数据模型

### 7.1 实体关系

| 模型 | 关键字段 | 说明 |
|------|----------|------|
| **User** | _openid, nickName, avatarUrl, intro, serviceTags, subscribeCount, reminderEnabled | 每个用户唯一标识；subscribeCount 为全局共享的提醒推送额度 |
| **Relationship** | ownerId, contactId, degree(1\|2), source(invite\|join_request\|card_coop), lastInteractAt, interactCount | 一度=邀请建立；二度=申请审批通过建立 |
| **Card** | _id, id, refCode, creatorId, title, desc, keyPoints[], deadline, reminderSetBy[], helperIds[], isNetworkVisible, status, createdAt, updatedAt | 记事卡本体；status 为内部字段，展示状态为系统判定三态 |
| **JoinRequest** | cardId, applicantId, intermediaryId, note, status(pending_intermediary\|pending\|approved\|rejected), createdAt, updatedAt | 申请加入凭证；pending_intermediary=待引荐 |
| **Message** | _openid, type(card_expired\|reminder\|join_request\|join_result\|member), title, content, cardId?, requestId?, read, createdAt | 站内消息（收件箱），由各业务云函数写入 |

### 7.2 状态体系（系统判定三态）

面向用户的卡片状态为系统判定，用户不可选择，无「完成」概念：

| 状态 | 判定规则 |
|------|----------|
| **已过期** | deadline 早于今天（对所有卡生效，不豁免历史 done 卡；无 deadline 不算过期） |
| **提醒中** | 未过期，且我的 openid 在该卡 reminderSetBy 数组里 |
| **未设提醒** | 未过期，且我的 openid 不在 reminderSetBy 里 |

多方规则：谁订阅就提醒谁，互不影响；过期状态对所有人照常生效。二度访客视角只区分「已过期/进行中」（提醒状态对未加入者无意义）。

### 7.3 权限矩阵

| 操作 | 创作者 | 一度协助者 | 二度访客 |
|------|--------|-----------|---------|
| 查看 | 完全 | 完全 | isNetworkVisible=开时可见 |
| 编辑内容 | ✓ | 部分（待确认） | ✗ |
| 邀请协作（分享） | ✓ | ✓ | ✗ |
| 接受邀请 | — | — | ✓（经分享链接，直接加入） |
| 审批申请 | ✓ | ✗ | ✗ |
| 帮 TA 引荐 | ✗（须非申请人） | ✓（须为指定引荐人+卡主一度人脉） | — |
| 申请加入 | — | — | ✓（经 view=network 入口） |

## 8. 假设与约束

### 8.1 假设

- 用户已熟悉微信小程序的基本操作（下拉、分享、订阅消息授权）
- 微信 AI（元宝）已上线聊天记录总结能力，可作为A路径的依赖
- 用户愿意授权剪贴板读取（iOS需手势触发）
- 云开发免费额度足够支撑MVP阶段的AI调用量
- 关系链扩散控制在一度邀请+二度引荐两级，可防止信任稀释

### 8.2 约束

- **技术约束**：小程序无法主动读取聊天记录（微信隐私红线）；普通3P小程序无API接收被转发的聊天文本；微信订阅消息授权一次只能推一条（额度制）
- **平台约束**：仅微信小程序；依赖微信订阅消息模板（模板 15788 待办事项提醒）
- **成本约束**：混元Token免费额度有限，需设计成本护栏（先本地规则、再AI兜底、结果缓存）
- **合规约束**：内容安全需经用户主动复制/选择后才进入AI处理流程

### 8.3 风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| 微信AI（元宝）接口不稳定 | 高 | 中 | C路径（剪贴板）始终可用，确保核心流程不中断 |
| 用户不理解二度人脉概念 | 中 | 中 | 教育性空状态+引导文案+视觉分层 |
| 订阅消息授权率低 | 中 | 中 | 在关键节点（建卡引导/详情订阅/互助页订阅胶囊）引导授权；额度耗尽写站内消息引导重新订阅 |
| 混元Token超支 | 高 | 低 | 成本护栏：本地规则优先、结果缓存、小模型配置 |
| 关系链扩散失控 | 中 | 低 | 一度邀请+二度引荐两级控制，引荐须卡主一度人脉 |
